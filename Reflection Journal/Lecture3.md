# Lecture 3: Development Environment Configuration, Build Tools, and Java 2D Graphics Rendering

**Date:** 13 August 2026  
**Course:** CSC360 — Computer Graphics and Interaction

---

The third lecture centered on configuring an end-to-end development workflow for graphics programming and implementing foundational two-dimensional drawing techniques in Java. We began by setting up Apache Maven as our primary build automation and dependency management tool, establishing a standardized project structure that simplifies packaging, testing, and lifecycle management for graphical applications. To streamline version control management on desktop environments, we installed and configured TortoiseGit, which provides an intuitive graphical interface for Git operations such as staging, committing, branching, and synchronizing repositories with remote hosts. Furthermore, we configured the Antigravity development environment by installing dedicated Java runtime extensions, language server tooling, and debugging utilities to ensure a seamless compile-and-run workflow for graphical codebases.

Moving from tool configuration to practical implementation, we developed a standalone Java program utilizing the standard Swing and Abstract Window Toolkit (AWT) packages to render fundamental geometric primitives. The core architecture relies on extending the JPanel class and overriding the paintComponent(Graphics g) method. Within this method, calling super.paintComponent(Graphics g) ensures proper surface clearing and background rendering before any custom graphics operations take place. By leveraging the Graphics context, we manipulated the graphics state machine by switching drawing colors dynamically using the Color class and rendering precise shapes based on screen coordinate offsets. 

The practical code demonstrated how different primitive drawing methods operate on pixel coordinates across the canvas. We rendered a horizontal red line using drawLine by defining discrete start and end coordinates (x1, y1, x2, y2), an outlined blue rectangle using drawRect with designated origin coordinates and dimensions, a solid filled green circle using fillOval where equal width and height values generate a true circular boundary, and an outlined orange ellipse using drawOval. The program encapsulates this custom drawing panel inside a configured JFrame window container, setting explicit dimensions, centering the window relative to the screen, defining default exit-on-close operations, and triggering visibility. This hands-on implementation reinforced how continuous mathematical coordinates are translated into discrete screen pixels through the paintComponent rendering cycle, forming the foundation for future interactive and dynamic graphics applications.
