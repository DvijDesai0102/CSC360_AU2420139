# Lecture 5: Markdown Standards, Geometric Constructions, and Object-Oriented Java Graphics Architecture

**Date:** 20 August 2026  
**Course:** CSC360: Computer Graphics and Interaction

---

The fifth lecture provided a dual focus on academic documentation hygiene and the programmatic architecture of graphical user interfaces in Java. The session opened with a peer review of classmates' Markdown reflection files to establish clear quality standards for our repository journals. We analyzed the structural dos and don'ts of writing technical reflections, emphasizing that notes should move beyond superficial summaries and instead capture personal learning breakthroughs, algorithmic logic, and conceptual connections across topics. We also explored Markdown syntax formatting techniques, such as proper header hierarchies, tabular data organization, code blocks, and blockquotes. To preview and inspect these Markdown documents locally without launching a heavy Integrated Development Environment, we examined standalone lightweight viewers, browser extensions, and command-line tools like grip or markdown-preview utilities that render GitHub-flavored Markdown natively.

We then transitioned to fundamental Object-Oriented Programming principles underpinning Java graphics frameworks, focusing on inheritance, class hierarchies, and anonymous classes. We examined how subclasses inherit and extend the state and behavior of parent classes, noting proper inheritance nomenclature where a specialized class extends a broader base class, such as class SweetApple extending class Apple. The concept of anonymous inner classes was highlighted as an essential technique for rapid event handling and inline component customization, allowing developers to override methods on the fly without declaring formal standalone classes.

The discussion then clarified the architectural workflow required to construct graphical applications in Java Swing. Rather than placing a frame into a panel, the standard architectural pattern dictates creating a top-level JFrame container to serve as the application window, configuring its lifecycle properties such as size, visibility, and close operations, and then nesting custom JPanel drawing surfaces directly inside that frame. Within the custom panel class, overriding the paintComponent(Graphics g) method forms the core rendering loop. Invoking super.paintComponent(g) remains mandatory to clear the surface and prevent visual artifacts. Using the Graphics context, developers dynamically assign stroke properties and color states using the Color class before executing drawing instructions with specific parametric arguments to render visual primitives on screen. We also walked through the process of embedding interactive UI controls, such as instantiating a JButton and adding it directly to a JFrame container to demonstrate basic event-driven layouts.

In addition to UI construction, we analyzed the geometric algorithms required to construct 2D shapes mathematically from discrete coordinate points. We derived how a rectangle can be generated using two diagonal anchor points, (x1, y1) and (x2, y2), where the origin coordinates are determined using min(x1, x2) and min(y1, y2), while the width and height are calculated from the absolute differences |x2 - x1| and |y2 - y1|. Building upon multi-point geometry, we explored constructing triangles using three coordinate pairs, (x1, y1), (x2, y2), and (x3, y3), using drawPolygon or fillPolygon. We analyzed how two points can be generated randomly within a defined coordinate range, whereas the third point must be selected carefully to prevent collinearity, ensuring that the three points do not lie on the same straight line and instead form a non-degenerate, visually stable polygon.

Finally, we systematically reviewed the universal Java syntax and structural conventions that form the baseline of this entire course. We broke down the role of import declarations like javax.swing.* and java.awt.* for accessing windowing toolkits, class declarations, access modifiers, and the precise execution mechanics of the public static void main(String[] args) entry point. We also reinforced strict Java naming conventions, such as CamelCase for classes and camelCase for methods, and examined how argument passing governs methods like drawLine, drawRect, fillOval, and drawPolygon. This session solidified the link between disciplined software architecture, core Java syntax, and procedural geometry rendering.
